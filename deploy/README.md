# الانتقال بتغيير الصورة فقط

احتفظ **بالستاك الحالي نفسه** وغيّر قيمة `image` فقط إلى الصورة الشخصية المختبرة
بعد نشرها. لا تستبدل ملف الستاك بقالب آخر، ولا تغيّر اسم المشروع أو الخدمة أو
الفوليومات أو الشبكة أو المنافذ أو إعداد `runtime` أو سطر `PATH`.
لهذا أُزيل قالب الانتقال السابق ومتغيراته الإضافية؛ ليس مطلوبًا معرفة أسماء
الفوليومات الفعلية وإعادة تعريفها كـ `external` للانتقال بهذه الطريقة.

تبقى وحدتا التخزين كما هما:

```yaml
volumes:
  - hermes-data:/home/agent/.hermes
  - hermes-webui-data:/home/agent/.hermes-web-ui
```

## لماذا تبقى تثبيتات الوكلاء؟

الصورة تضبط تثبيتات مدير الوكلاء الجديدة داخل
`/home/agent/.hermes/coding-agent/npm`؛ لذلك يحفظها فوليوم هرمز الموجود أصلًا.
مدخل Docker يضيف مسار الأوامر داخليًا حتى لو كتب الستاك القديم `PATH` يدويًا.
لا ننقل ملفات النظام كلها، ولا نغيّر `HOME` أو منازل البروفايلات أو سلوك سطح المكتب.

التثبيتات السابقة المحفوظة تحت `.hermes-web-ui/coding-agent/npm` تظل قابلة
للاكتشاف كمسار احتياطي، دون نسخها أو حذفها أو استبدالها تلقائيًا. تثبيتات الطبقة
المؤقتة في الحاوية القديمة لا تنتقل بمجرد تغيير الصورة؛ قد تحتاج إعادة تثبيت
واحدة عبر Studio. بعد تثبيتها في المسار الجديد تبقى عند استبدال الحاوية.
هذا خاص ببرامج الوكلاء، وليس وعدًا بنقل كل ملفات الدخول الأصلية خارج الفوليومات.

## قبل وبعد التبديل

1. احتفظ بالصورة القديمة وخذ نسخة احتياطية متسقة من وحدتي البيانات بعد إيقاف
   الكتابة إليهما. لا تستخدم `down -v` ولا تحذف الفوليومات.
2. انتظر نشر الصورة واجتياز فحوصها. المستودع والصورة خاصّان؛ يحتاج مدير الستاك
   اعتماد قراءة `GHCR`، دون وضع الرمز في YAML أو Git أو المحادثة.
3. غيّر `image` فقط في **الستاك القائم** ثم أعد نشر الخدمة. لا تنشئ ستاكًا جديدًا
   يكتب في البيانات نفسها. أبقِ إعدادات الوكيل العكسي والقنوات كما هي.
4. تحقق من حسابك وبروفايلاتك ومحادثاتك، ثم اختبر مزودك وقناتك. اختباراتنا المعزولة
   لا تعوّض اختبار شبكة السيرفر ومزوديه. إعادة التشغيل وحدها لا تختبر البقاء؛
   الاختبار الصحيح هو إعادة إنشاء الحاوية مع الاحتفاظ بالفوليومات.

عند التراجع، قد تحتاج استعادة نسخة البيانات مع الصورة القديمة إذا حدثت ترحيلات
لقواعد البيانات. لا نغيّر سيرفر المستخدم تلقائيًا.

## إصدار الصورة

البناء الشخصي يدوي في `personal-image.yml`، ويشترط نجاح `Build` و`Playwright`
وحارس الرخصة لنفس commit المصدر قبل البناء والنشر، ثم يجري فحص تشغيل الصورة.
يُتحقق من خصوصية المستودع والحزمة؛ لا نشر إلى حساب المطور ولا تحويلها إلى عامة.
مصدر Hermes الأساسي مثبت ببصمة ويُحدّث عمدًا بعد المراجعة.

البناء الحالي يستهدف `linux/amd64` فقط؛ أجهزة ARM تحتاج صورة مختبرة لمعمارية ARM.
استخدم وسم `sha-<commit>` المراجع أو digest ثابتًا، وليس `latest` غير مراجع.
تغيير الصورة فقط يخص الستاك المتوافق الذي يحفظ مجلدي Hermes وStudio؛ لا يضمن
توافق كل تعديلات المستخدمين أو بيانات الإصدارات المستقبلية دون فحص.
