## المشكلة والهدف

طلب عاصم تصميم شعار باسم Core Hub يتناسب مع منصة تنسّق عدة ايجنتات، ويصلح للتطبيق واستخداماته الأخرى. الاسم الحالي مؤقت بحسب docs/PERSONAL-FORK.md؛ تغيير اسم المنتج العام ينفذه صاحب الريبو. الهدف في هذا الطلب تقديم تصور بصري قابل للمراجعة داخل الريبو الخاص.

## القرار والموافقات

الرمز المقترح بوابة C تحيط بنواة مربعة مستقلة، مع نسخة أفقية للاسم وأيقونة مستقلة. صُممت التصورات بمساعدة أداة image_gen، وتحفظ أوامرها للمراجعة. طلب عاصم اتباع شروط المشروع ورفع PR ليعتمده المالك؛ هذا الطلب مسودة تصميم ولا يمثل اعتماد الهوية أو تفويضًا بالدمج إلى main.

يشمل النطاق صور المقترح ودليل استعماله فقط. يبقى اختيار الهوية وموعد تبديل أصول التطبيق لصاحب المشروع. لا تغيير لمعرفات البروتوكول أو أسماء الحزم أو مسارات البيانات أو ملفات الرخصة والنسب.

## الملفات والتأثير

- docs/branding/core-hub/: لوحة الهوية، الرمز الشفاف، أيقونة التطبيق، أوامر التوليد ودليل الاستخدام.
- هذا السجل يوثق النطاق والتحقق والتسليم.

الأصول للمراجعة ولا تستوردها ملفات التشغيل؛ لا أثر على الواجهة الحالية أو Docker أو desktop. عمل النسخة التجريبية وبيانات المستخدم خارج هذا الفرع.

## الفحوص

على الفرع المشتق من origin/main 51db3b587c9070ef9665a06a5bc1b4d66872e0bd، ببيئة Node.js 24.16.0 وmacOS arm64، وبعد اكتمال حزمة التصور:

- npm run harness:check: نجح، بما فيه توثيق API لـEkko.
- npm run test:personal: نجحت الاختبارات الثمانية.
- npm run license:check: نجح؛ الرخصة الأصلية محفوظة.
- التحقق من بنية سجل المهمة وgit diff --check: نجحا.
- فحص بصري للصور الثلاث، وقراءة بيانات PNG: اللوحة 1536×1024 معتمة؛ الرمز 1254×1254 بشفافية فعلية؛ أيقونة التطبيق 1254×1254 معتمة.

استخدم فحص harness نسخة TypeScript 6.0.3 المحلية المطابقة لقفل هذا الريبو، عبر رابط داخل node_modules غير المتتبع. لم ينفذ تثبيت كامل للاعتماديات أو build أو e2e محليًا لأن النطاق صور توثيقية لا يستوردها التطبيق؛ CI يفحص الفرع بتركيبة كاملة. هذه نتائج محلية ولا تعني نجاح CI أو اعتماد التصميم. لا تُنسب فحوص النسخة المحلية القديمة إلى هذا الفرع.

## المخاطر والرجوع

لا تغيير في البيانات أو المصادقة أو عقود API أو اللغة واتجاه النصوص. الصور مقترحات raster؛ ليست ملفات vector نهائية أو حزمة أيقونات أصلية لكل نظام. يلزم إعداد مصادر SVG واختبار المقاسات الصغيرة وملفات ICO/ICNS/متطلبات Icon Composer عند اختيار التصميم. العودة بإزالة مجلد التصور وسجله فقط؛ لا ترحيل بيانات.

الحزمة جاهزة للمراجعة على فرع المهمة من origin/main؛ يربط طلب المراجعة هذا السجل ويذكر رأس الفرع وحالة CI الفعلية. الخطوة التالية اختيار المالك للاتجاه قبل إعداد أصول التطبيق النهائية أو تغيير الاسم. ينسخ فرع المهمة إلى test وفق مسار التعاون، ولا تحتاج مساهمة التوثيق هذه بناء صورة جديدة وفق TEAM-RULES §7. لا دمج إلى main ولا ترقية latest أو نشر على السيرفر ضمن هذا التغيير التوثيقي.
