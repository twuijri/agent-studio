# تأسيس قواعد تطوير الفريق والمساعدين

المسؤول: twuijri
الفرع: docs/team-development-rules
الحالة: review

## المشكلة والهدف
طلب صاحب المشروع قواعد مشتركة لفريق يطور يدويًا أو بمساعدة Codex وClaude،
مع توثيق كل مهمة حتى لا تضيع المعرفة وتتكرر التحليلات. لم يكن هناك مدخل
CLAUDE.md أو سجل موحد البنية لتسليم مهام الفريق أو قالب مراجعة خاص بالنسخة.

## القرار والموافقات
أُجيز إعداد قواعد العمل. السياسة في مرجع واحد، وCLAUDE.md يستورد AGENTS.md
بدل نسخ القواعد. سجل مستقل لكل مهمة يقلل التعارض على ملف مشترك كبير.
في المتابعة أذن صاحب المشروع برفع جميع هذه التعديلات، وطلب أن يعمل الجميع على
فروع وأن يكون قرار الدمج وتنفيذه له وحده بعد الفحوص والتحقق من التعارضات.
سيُرفع فرع المهمة بطلب دمج؛ لا إذن بتنفيذ الدمج أو نشر صورة أو تعديل السيرفر.

## الملفات والتأثير
قوانين الفريق ومدخل المساهمين وتعليمات المساعدين ودليل المعرفة، وقالب PR،
وسجلات التغيير، وفحصها واختباراته. لا تغييرات في كود التطبيق أو الصورة أو الستاك.

## الفحوص
فحوص محلية بتاريخ 2026-09-15:

- `npm run test:personal` باستخدام `Node.js 24` و`npm 11`: نجحت الاختبارات الثمانية،
  ومنها ثلاثة لفحص التعليمات وسجلات المهام، دون إخفاقات أو اختبارات متخطاة.
- `npm run harness:check` بالبيئة نفسها: نجح، بما فيه مطابقة توثيق واجهة Ekko.
- تحقق مباشر باستخدام مكتبة `yaml` من إعداد حدث PR وصلاحيات القراءة وعدم إبقاء
  بيانات اعتماد checkout، وفحص روابط القواعد المحلية وبنية سجل هذه المهمة: نجح.
- `git diff --check`: نجح.

اختبار سجل PR يستخدم مستودع Git مؤقتًا ويثبت رفض السجل الناقص أو غير المحفوظ
في commit، وقبول السجل الجديد أو المحدّث. لم يُشغّل workflow على GitHub بعد.
لم تُعد اختبارات التطبيق الشاملة أو بناء الصورة؛ التغيير تعليمات وقوالب وفحص تطوير،
ولا يغيّر تشغيل التطبيق. ظهرت تحذيرات npm عن إعدادات بيئة قديمة، دون فشل الفحوص.

## المخاطر والرجوع
فحص السجل يثبت البنية لا صدق المحتوى. استعلاما حماية main وrulesets أعادا
رفضًا من GitHub يتطلب Pro للمستودع الخاص؛ تعذر تفعيل الحماية بالخطة الحالية.
لم نغيّر الاشتراك أو ظهور المستودع أو صلاحيات المتعاونين. ظهر حساب المالك وحده
في قائمة المتعاونين. السياسة ليست منعًا تقنيًا لمن يُمنح صلاحية كتابة لاحقًا.
الرجوع عن هذه الإضافة لا يغير بيانات المستخدم أو صورة latest.

## التسليم والخطوة التالية
الرفع مأذون على فرع `docs/team-development-rules`، والدمج متروك لصاحب المشروع.
تُراجع نتائج CI وحالة التعارض في طلب الدمج بعد رفعه؛ النتائج المحلية أعلاه لا
تُعد نتائج CI. يجب حل قيد خطة GitHub قبل الادعاء بفرض حصر الدمج تقنيًا.
لم يُدمج شيء ولم تُنشر صورة ولم تتغير صلاحيات المشاركين أو بيانات الإنتاج.
