# الإصدار الأول v1.0.0: رفع رقم الإصدار

المسؤول: twuijri
الفرع: release/v1.0.0
الحالة: review

## المشكلة والهدف
المالك قرر إصدار النسخة الأولى من كور هب باسم `v1.0.0` مع تطبيقات سطح المكتب لكل
المنصات وصورة Docker. رقم الإصدار في الحزم كان `0.7.21` (رقم Ekko Studio الأصلي)
فتحمل الملفات والواجهة رقماً لا يخصنا.

## القرار والموافقات
- الموافقة: المالك (2026-09-18: «ابي انزل كل التطبيقات للماك وكل شي خلاص نسخة
  أولى v1.0.0»)، واعتمد الترقيم المستقل عن upstream.
- رفع `version` إلى `1.0.0` في `package.json` و`package-lock.json` الجذريين وفي
  `packages/desktop/package.json` و`packages/desktop/package-lock.json`. أسماء
  ملفات التطبيق تصير `Core.Hub-1.0.0-<arch>` ورقم الواجهة `1.0.0`.
- مسار الإصدار بعد الدمج: إنشاء الإصدار/الوسم `v1.0.0` من `main`، ثم بناء صورة
  Docker بـ `source_ref=v1.0.0` و`publish_latest=true`، ثم «Publish Desktop
  Artifacts to Release» بالوسم نفسه. الإنشاء والنشر بقرار المالك.

## الملفات والتأثير
ملفات الحزم الأربعة وهذا السجل. لا تغيير في الكود. دمج تحديثات upstream
اللاحقة قد يتعارض على حقل الإصدار؛ يُحلّ بالإبقاء على رقم كور هب.

## الفحوص
صحة JSON للملفات الأربعة؛ فحص القفل في CI (`NPM Lockfile Check`)؛ `git diff --check`.

## المخاطر والرجوع
لا خطر تشغيلي. الرجوع بإعادة الرقم.

## التسليم والخطوة التالية
طلب دمج إلى `main` مع دمج الفرع في `test`، ثم خطوات الإصدار أعلاه.
