# بث ملفات الوسائط المحلية مع دعم Range بدل قراءتها كاملة في الذاكرة

المسؤول: twuijri
الفرع: fix/media-download-streaming
الحالة: review

## المشكلة والهدف
بعد أن صدّر هيرمس فيديو عبر DaVinci (وضع محلي عند صديق المالك)، ظهر مشغّل
الفيديو في الدردشة جامدًا عند 0:00 بلا خطأ. مسار `/api/studio/files/download`
كان يقرأ الملف كاملًا في الذاكرة بحد أقصى للحجم (`file_too_large` → 413)
وبلا دعم لطلبات `Range`، بينما مشغّل المتصفح يحتاج استجابات 206 للبدء والتقديم،
والفيديو الكبير يتجاوز الحد فيُرفض بصمت داخل المشغّل.

## القرار والموافقات
- الموافقة: المالك (2026-09-19: وصف المشكلة «يضغط يكون جامد»).
- عندما يكون مزوّد الملفات محليًا (السيرفر نفسه أو السيرفر المضمّن في التطبيق)
  ولا يُطلب متغير `app-image`: يُبث الملف من القرص عبر `createReadStream` مع
  `Accept-Ranges: bytes`، و206 مع `Content-Range` لطلبات النطاق، و416 للنطاق
  غير الصالح، بلا حد للحجم. الفيديو والصوت يُرسلان `inline` والباقي `attachment`.
- المزوّدات الأخرى (docker/ssh/…) كما هي (قراءة مؤقتة عبر المزوّد).

## الملفات والتأثير
`packages/server/src/modules/studio/controllers/download.ts`،
`tests/server/download-streaming.test.ts` (جديد).

## الفحوص
- الاختبار الجديد: بث كامل مع الترويسات، نطاق جزئي 206، نطاق مفتوح، نطاق غير
  صالح 416، المستندات تبقى attachment، 404 للملف المفقود.
- فحص أنواع السيرفر، اختبارات السيرفر ذات الصلة، `git diff --check`.
- التحقق الفعلي عند صديق المالك بعد تحديث تطبيق التست (سيرفر محلي) أو الصورة.

## المخاطر والرجوع

  القراءة المؤقتة.
