# الكانبان: خمسة أعمدة وصندوق وارد وحالة المهمة على البطاقة

المسؤول: twuijri
الفرع: feat/kanban-compact-board (يبني فوق feat/kanban-board-dnd، PR #3)
الحالة: review

## المشكلة والهدف
بعد تجربة لوحة السحب على ستاك التجربة، رأى صاحب المشروع أن تسعة أعمدة كثيرة
وغير عملية. تحليل مصدر Hermes أكد أن الحالات التسع حقيقية ولا تُحذف، لكن العرض
حر في تجميعها. الهدف: لوحة بصندوق وارد ضيق للفرز وخمسة أعمدة عمل (الطابور =
للتنفيذ + جاهزة، قيد التشغيل، بانتظار = مجدولة + محجوبة، المراجعة، منتهية مع
المؤرشف تحتها)، مع لغة حالة على البطاقة نفسها (إطار أخضر دوّار للتشغيل، أحمر
ثابت للمحجوبة، كهرماني متقطع مع ساعة للمجدولة، بنفسجي للمراجعة، شارة «جاهزة»)
لأن الدمج يحتاج تمييز الحالة بلا عمود.

خارج النطاق: أي تغيير في الخادم أو في Hermes؛ أرشفة عكسية (Hermes لا يملك
أمر إلغاء أرشفة، فالمؤرشف يُعرض للاطلاع فقط)؛ الطيّ التلقائي للأعمدة الفارغة.

## القرار والموافقات
اعتمد صاحب المشروع بتاريخ 2026-09-17 الشكل النهائي بخمسة أعمدة وصندوق وارد
مع اللغة البصرية للبطاقات، كمهمة واحدة. الافتراضات المعلنة له:

- الطابور: الجاهزة تحمل شارة، وبطاقة «للتنفيذ» لها زر «ترقية» لأن السحب داخل
  العمود نفسه ترتيب لا انتقال.
- بانتظار: إفلات بطاقة عليه يفتح اختيارًا (تأجيل = `schedule`، حجب = `block` بسبب)
  لأن Hermes يفرّق بينهما بأمرين.
- منتهية: رابط «إظهار المؤرشف (n)» يعرض المؤرشف للاطلاع، والأرشفة زر على البطاقة
  المنتهية بتأكيد.
- الوارد: شريط ضيق بعدّاد يتوسع لعرض مهام الفرز؛ لا يقبل الإفلات؛ التحديد من
  نافذة التفاصيل.
- شريط الإحصائيات يبقى بالحالات التسع لأنه فلتر؛ الفلتر يعرض العمود الحاوي للحالة.
- تعطيل الحركة عند `prefers-reduced-motion`.

الدمج في `test` وبناء صورة `test` ضمن التفويض الدائم؛ الدمج في `main` قرار المالك.

## الملفات والتأثير
- `utils/hermes/kanban-board.ts`: تعريف الأعمدة، خيارات الإفلات لكل عمود مشتقة من
  خريطة الانتقالات نفسها، الترتيب المحلي مفتاحه معرّف العمود.
- `stores/hermes/kanban.ts`: `orderedTasksForColumn`، `tasksWithStatus`، `setCardOrder(column)`.
- `KanbanTaskCard.vue`: جسم البطاقة `role="button"` مع زر سريع متداخل، شارات
  وأيقونات الحالة، الإطارات والحركات.
- `KanbanColumn.vue`: عمود بحالات متعددة، قسم المؤرشف، حارس الإفلات بحالة
  البطاقة المسحوبة.
- `KanbanView.vue`: الأعمدة الخمسة، الشريط الوارد، نافذة اختيار نوع الانتظار،
  الإجراءات السريعة.
- ملفات اللغات الإحدى عشرة (`kanban.board.*`).
- الاختبارات: `kanban-board-utils`، `kanban-column`، `kanban-task-card`، `kanban-view`،
  `kanban-store`، `tests/e2e/kanban-board.spec.ts`.

  حالات جديدة لخريطة الأعمدة وخيارات الإفلات، وشارات البطاقة والزر السريع
  ولوحة المفاتيح، وقسم المؤرشف، ونافذة اختيار نوع الانتظار، والشريط الوارد.

  14 متجاوزة، 0 فشل.
- `PLAYWRIGHT_CHANNEL=chrome npx playwright test tests/e2e/kanban-board.spec.ts --workers=1`:
  5 ناجحة (رفض `todo → running`، ترقية بزر البطاقة، `ready → review` بالسحب،
  `ready → بانتظار` مع اختيار الحجب وسبب، ترتيب البطاقات المحلي، العجلة الأفقية،
  الوارد والمؤرشف).
- `npm run harness:check`، `npm run test:personal` (8)، `git diff --check`: نجحت.
- لقطات Playwright: إنجليزي فاتح، عربي داكن مع حالة السحب (تعتيم «قيد التشغيل» وإبراز
  «بانتظار»)، جوال 390px؛ الحلقات والشارات والشريط الوارد ظاهرة كما صُممت.

لم يُختبر: Hermes حقيقي، اللمس على جهاز فعلي، `prefers-reduced-motion` في متصفح حقيقي
(القاعدة موجودة في CSS فقط).

تعديل بطلب المالك (2026-09-17، بعد رؤية النسخة الأولى على ستاك التجربة): «قيد
التشغيل» ليست عمودًا مستقلًا بل المرحلة الثالثة داخل الطابور (عادية ← جاهزة بشارة
← قيد التشغيل بإطار أخضر دوّار في مكانها). الأعمدة صارت أربعة: الطابور، بانتظار،
المراجعة، منتهية، مع الشريط الوارد. حراس الانتقال بالحالة لم تتغير: بطاقة قيد
التشغيل لا تُنقل داخل الطابور إلا ترتيبًا، وتقبل السحب إلى المراجعة أو بانتظار أو
منتهية كما يسمح Hermes.
