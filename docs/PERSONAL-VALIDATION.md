# فحص تأسيس إيجنت استديو

التاريخ: 2026-09-15. النسخة الأساسية `0.7.21`، وآخر `upstream/main` وقت الفحص:
`51fd3c86d471c5f1acc5d3397839a89aeba2431a`.

## نطاق الدمج

جرت مراجعة 43 مساهمة للمستخدم `twuijri`:

- 21 موجودة أصلًا في تاريخ النسخة الأساسية.
- 17 أُدمج تاريخها في الفرع الشخصي، مع إبقاء التنفيذ الحديث عندما كان مكافئًا.
- 4 استُبدلت بإصلاحات أحدث من المطور؛ البدائل مسجلة في `personal-pr-inventory.json`.
- مساهمة عميل أندرويد أُعيدت كمصدر تجريبي غير معتمد للإصدار.

من إصلاحات التوافق أثناء الدمج: تسجيل مسارات الويب هوك الوارد في نقطة تركيب
المسارات الحديثة، ونقل اكتشاف أمر Hermes إلى وحدة التشغيل الحالية مع الحفاظ
على معالجة Windows، وتحديث اختبار اسم خادم MCP لمطابقة الاسم الحالي.

## الفحوص

أُجريت الفحوص باستخدام Node.js 24 وChrome المحلي. اختبارات المتصفح تستعمل
خادم واجهة وواجهات API اختبارية، وليست تجربة على سيرفر المستخدم أو مزود مدفوع.

- بناء الواجهة والخادم: ناجح.
- بناء TypeScript لسطح المكتب: ناجح، وليس حزمة تثبيت موقعة.
- فحص حدود الوحدات والتوثيق `harness:check`: ناجح.
- الاختبارات مع التغطية بعد تحديث الاعتماديات: 5623 ناجحة، و14 متجاوزة حسب إعدادات المشروع، بلا فشل.
- اختبارات المتصفح عند التأسيس: 204 ناجحة، بما فيها صفحة الاتصال العربية واتجاه النص؛ جولة التحديث موضحة أدناه.
- اختبارات حماية الرخصة والتحديث المعزول: 5 ناجحة.
- صياغة `compose.personal.yml` وقالب انتقال السيرفر: سليمة.
- الرخصة في المصدر ومخرجات البناء مطابقة بايتًا للرخصة الأصلية.
- فُحصت صفحة الاتصال بصريًا بالعربية والإنجليزية؛ عنوان السيرفر يبقى باتجاه يسار إلى يمين.

أوامر إعادة الاختبار:

```bash
npm run test:coverage -- --testTimeout=15000 --maxWorkers=4
PLAYWRIGHT_CHANNEL=chrome npm run test:e2e -- --workers=4
npm run test:personal
npm run harness:check
npm run build
npm --prefix packages/desktop run build
docker compose -f compose.personal.yml config --quiet
```

حُدّدت عمال الاختبار بحد أقصى أربعة، مع مهلة أطول لتحميل شجرة مسارات السيرفر
تحت قياس التغطية. الجولة الأولى تجاوزت مهلة خمس ثوانٍ في اختباري ترتيب مصادقة
الصوت. لا تشغّل فحص المتصفح بالتزامن مع تعديل الواجهة؛ إعادة التحميل التطويرية
قد تُغلق النوافذ أثناء الاختبار وتبطل النتيجة.

بعد تحديث الاعتماديات، نجحت 200 حالة متصفح وفشلت 4 أثناء إعادة تحميل وحدات
خادم التطوير. في الجولة التالية دون تغيير الكود نجحت هذه الحالات وبلغ النجاح
203، مع إخفاق انتظار بطاقة مزود في حالة أخرى. أعيد ملف المزود كاملًا بعامل
واحد ونجحت حالاته الـ16. لا نخلط هذه النتائج مع جولة واحدة كاملة خالية من الفشل؛
نشر الصورة يشترط نجاح جولة GitHub الكاملة بعامل واحد وفق إعداد المشروع.

بُنيت صورة Linux محليًا مع Hermes `0.21.3`. كشف فحصها الأول أن التطبيق يبدأ
افتراضيًا على `8648` بينما الصورة تعلن `6060`؛ `EXPOSE` وحده لا يضبط التطبيق.
أضيف `ENV PORT=6060`. ستاك المستخدم الأصلي يحدد هذا المتغير أصلًا فلا تنسب إليه
هذه المشكلة. إعادة فحص الصورة المصححة شرط قبل اعتمادها للنقل.

## مراجعة الاعتماديات قبل النشر

أبلغ `npm audit --omit=dev` وقت الفحص عن 6 تحذيرات إنتاج في الجذر
(4 عالية و2 متوسطة)، وعن 4 في حزمة سطح المكتب (واحد حرج و3 عالية).
تشمل الحزم المباشرة `axios` و`sharp` و`adm-zip`، وفي سطح المكتب `tar`
و`electron-updater`. أرقام إصدارات هذه الحزم مطابقة للنسخة الأساسية؛
لم تُضفها تغييرات الفرع الشخصي. التقرير لا يثبت وحده إمكانية استغلال التطبيق،
ولا يكفي نجاح الاختبارات لإثبات سلامته الأمنية.

بعد مراجعة خطة التحديث نُفّذت الإصلاحات داخل نطاق الإصدارات المسموح، دون
`--force`. حُدّثت الحزم المباشرة وغير المباشرة في ملفات القفل، ومنها
`adm-zip 0.6.1`، `axios 1.20.0`، `sharp 0.35.4`، `form-data 4.0.6`،
`nanoid 3.3.19`، `qs 6.16.0`. وفي سطح المكتب: `electron-updater 6.8.9`،
`tar 7.5.22` و`js-yaml 4.3.2`.

لا يكفي تجاهل حزم التطوير: بعضها يُضمّن في واجهة الإنتاج. لذلك رُفعت مكتبة
`pdfjs-dist` إلى الفرع السادس المصحح، وحُدّث استدعاء تنظيف المعاينة لاستخدام
مهمة التحميل التي تملك العامل في هذا الإصدار، وأضيف اختباران للإغلاق والاستبدال.
حُدّث `vite` إلى إصدار مصحح، وفُرض `dompurify ^3.4.15` تحت `monaco-editor`
مع إعادة حل القفل وإعادة التثبيت للتحقق من أن النسخة القديمة لم تبقَ متداخلة.

النتيجة بتاريخ 2026-09-15: صفر تحذيرات في `npm audit --omit=dev` للجذر، وصفر
في تقرير حزمة سطح المكتب الكامل. التقرير الكامل للجذر ما زال يعرض 6 تحذيرات
متوسطة في سلسلة أدوات التطوير `tsoa/ts-deepmerge` و`vitest` والتغطية.
لم نطبق الترقيات الرئيسية المقترحة عشوائيًا. لا تعرّض خادم اختبارات Vitest
للشبكة، ولا تعتبر هذا تدقيقًا أمنيًا شاملًا لصورة Linux أو Python أو كل البرامج
التي قد يثبتها المستخدم. استعد لهذه التحذيرات في مهمة ترقية أدوات تطوير مستقلة.

## حدود النتيجة

أُنشئ المستودع الخاص `twuijri/agent-studio` لرفع النسخة وفحصها في GitHub.
لا تُعدّ الصورة جاهزة للنقل إلا بنجاح CI وفحص تشغيلها ونشرها؛ يُراجع سجل
`Personal Agent Studio image` للـcommit المطلوب. لم تُنشر على سيرفر المستخدم
ولم تُنقل بياناته. أسماء فوليومات السيرفر ومعماريته وصلاحية سحب الصورة الخاصة
تحتاج تحققًا على السيرفر قبل تغيير الستاك.
لم يُبنَ عميل أندرويد التاريخي ولم يُختبر على جهاز، ولا تتضمن النسخة تطبيق iOS
الرسمي أو اشتراك خدمات المطور. طريقة الجوال الحالية هي واجهة الويب المباشرة.
لا تشمل هذه الجولة إرسال طلبات حقيقية مدفوعة لكل مزود صور أو نموذج أو قناة.
