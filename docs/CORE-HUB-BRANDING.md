# كور هب — الهوية وإعادة تسمية المستودع

اعتمد المالك `Core Hub` / «كور هب» بتاريخ 2026-09-17 بدل الاسم المؤقت Agent Studio.
الهوية خاصة بهذه النسخة، وليست ادعاءً بملكية كود EKKOLearnAI أو إعادة تسمية
Hermes Agent أو Ekko Agent أو بقية الوكلاء. تبقى LICENSE وNOTICE.personal.md
ورخص الجهات الأخرى ونسب المساهمات كما هي.

## مصدر الاسم والأيقونة

- نصوص العرض في لغات الواجهة، Electron، الإشعارات ووصف أدوات MCP تحمل الاسم الجديد.
  أسماء أدوات MCP وأوامر CLI وعناوين API تبقى ثابتة للتوافق.
- `packages/client/public/core-hub-mark.svg` أصل متجهي للرمز الذي أرسله المالك؛
  يعاد رسمه هندسيًا من المرجع، وليس الخط الطباعي لكلمة Core Hub.
- `node packages/desktop/scripts/generate-rounded-icons.mjs` يشتق ملفات الويب
  وPWA وICO وICNS وأيقونات Electron من الأصل نفسه باستخدام sharp الموجود أصلًا.
  لا نغير صور الوكلاء. يحتفظ `logo.png` باسمه لخدمة العملاء القدامى.
- لا تُعاد كتابة سجل الإصدارات أو المستندات التاريخية لإخفاء هوية المشروع الأصلي.
  README يوضح الفصل بين كور هب ومرجع upstream المحفوظ.
- `scripts/personal-branding.mjs` مساعد محدود لترحيل أسماء العرض؛ لا يُشغّل
  كبديل عن مراجعة تحديث upstream، ولا يغير معرّفات التخزين أو النسب.

## ثوابت التوافق

لا تتغير HERMES_HOME أو HERMES_WEB_UI_HOME أو `.hermes` أو `.hermes-web-ui`،
ولا الفوليومات أو مسارات API وIPC ومفاتيح localStorage وأسماء الوكلاء.
يحافظ سطح المكتب على `package.name=hermes-studio` و`appId=us.i3u.agentstudio`
وعلى userData قبل تغيير اسم العرض؛ تغييرها قد يفصل التطبيق عن بياناته القديمة.
أسماء مثبتات جديدة Core.Hub، لكن هوية حزمة Linux التنفيذية القديمة باقية.
تعامل Windows مع العمليات يحتفظ بالأسماء القديمة ويضيف Core Hub.

عنوان الصورة يبقى عمدًا:

```yaml
image: ghcr.io/twuijri/agent-studio:latest
```

ووسم التجربة يبقى `ghcr.io/twuijri/agent-studio:test`. تغيير اسم الريبو لا يعيد
تسمية حزمة GHCR؛ لا تنشئ حزمة جديدة أو تجعل الحالية عامة. لا حاجة لتعديل الستاك.

## الترتيب الآمن لإعادة تسمية الريبو

1. يراجع المالك طلب الهوية ويدمجه إلى main بعد نجاح الفحوص؛ لا يدمجه المساعد.
2. بعد الدمج فقط، يُغيّر اسم المستودع الخاص من `twuijri/agent-studio` إلى
   `twuijri/core-hub`. هذه الخطوة لم تُنفذ في طلب الهوية نفسه.
3. تحديث `origin` في كل نسخة محلية إلى `https://github.com/twuijri/core-hub.git`؛
   عدم تعديل upstream أو حذف المستودع/إنشاء بديل له.
4. التأكد من بقاء المستودع والصورة خاصين، وبقاء المتعاونين والطلبات والتاريخ،
   ومن ارتباط صلاحيات GitHub Actions بحزمة GHCR القديمة.
5. تشغيل مسار `Personal Core Hub image` من المصدر المراجع بعد نجاح CI على
   commit نفسه؛ تبقى حماية الرخصة والخصوصية واختبار الصورة قبل النشر مطلوبة.
6. بناء الصورة لا ينشرها على السيرفر. يسحب المالك الصورة ويعيد نشر الستاك عند اختياره.

النقل يحافظ على قبول الاسمين المحددين فقط في سير عمل الصور؛ لا يوسع النشر
إلى أي fork أو حساب آخر، ولا يغيّر صلاحيات collaborator أو حماية main.
