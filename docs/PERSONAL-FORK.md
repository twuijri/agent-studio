# كور هب — النسخة الشخصية

هذه نسخة شخصية غير تجارية باسم `Core Hub` مشتقة من مشروع
[EKKOLearnAI](https://github.com/EKKOLearnAI/hermes-studio).
اعتمد المالك اسم كور هب بدل الاسم المؤقت Agent Studio. أسماء بروتوكولات Hermes وEkko ومعرّفات النماذج ومسارات البيانات
تبقى متوافقة مع الأصل؛ إعادة تسمية هذه المعرفات آليًا قد تكسر البيانات والتكاملات.

نتائج الفحص وحدود الجاهزية وتحذيرات الاعتماديات: [سجل الفحص](PERSONAL-VALIDATION.md).
أسباب القرارات وذاكرة التطوير: [دليل المعرفة](KNOWLEDGE-WORKFLOW.md).
لاستبدال الصورة فقط مع الحفاظ على الستاك القديم: [دليل الانتقال](../deploy/README.md).
ملف `compose.personal.yml` أدناه لتجربة معزولة، وليس بديلًا عن ستاك المستخدم.

## الرخصة: قاعدة إلزامية لكل تعديل

**ممنوع حذف `LICENSE` أو تغيير صاحبه أو تجاهله أو تعطيل فحصه لتمرير البناء.**
احتفظ أيضًا برخص الأطراف الثالثة ونسب المساهمات. تغيير اسم الواجهة لا يغيّر ملكية
الكود أو شروط استخدامه. راجع `NOTICE.personal.md`. لا تعِد ترخيص الكود على أنه MIT.
الفحص في `scripts/check-personal-license.mjs` يتحقق من بصمة الرخصة الأصلية،
ويعمل قبل البناء وفي CI. ليس نظامًا يمنع صاحب الملفات تقنيًا من تعديلها؛ إنه
حاجز يمنع الحذف غير المقصود ويكشفه. أي رخصة مختلفة في تحديث جديد تستلزم مراجعة بشرية.

## التشغيل والبيانات

استخدم Node.js 24. لتثبيت الاعتماديات وبناء النسخة:

```bash
npm ci --ignore-scripts
npm rebuild node-pty
npm run build
```

بناء حاوية تجمع الاستديو وHermes Agent، مع بيانات مستقلة عن التركيب السابق:

```bash
docker compose -f compose.personal.yml build
docker compose -f compose.personal.yml up -d
```

المنفذ المحلي `6061`. للتشغيل على سيرفرك ضع وكيل HTTPS أمامه واضبط
`AGENT_STUDIO_PUBLIC_URL` على الرابط العام الصحيح قبل إنشاء رموز الربط.
لا تعرّض المنفذ مباشرة بلا إعداد المصادقة. افتح صفحة الويب على الجوال وأضفها
للشاشة الرئيسية. لا تحتاج حسابًا في خدمة المطور لهذا المسار.
الملف يستخدم وحدتي تخزين جديدتين. الانتقال ببياناتك القديمة يحتاج نسخة احتياطية
ومراجعة مساراتها؛ لم ننقل بيانات سيرفرك الحالي.

## الخدمات الرسمية والتحديث التلقائي

النسخة تعرض الاتصال المباشر وخيارات إشعاراتك الذاتية. صفحة الشراء وتنزيل التطبيق
الرسمي والربط السحابي الرسمي ليست ضمن الواجهة المستخدمة. خادم الربط السحابي
الرسمي متوقف، والإعلانات الرسمية متوقفة. رموز مستخدم السيرفر ومصادقة الأجهزة
ما زالت مطلوبة؛ لا نولّد صلاحية مدفوعة لخوادم المطور.
تحديث Studio من npm أو محدّث سطح المكتب متوقف كي لا يستبدل النسخة الشخصية.
تنزيل نسخ Web UI الرسمية وتفعيلها، وكذلك تشغيل نسخة المعاينة الرسمية، متوقف أيضًا.
تنزيل Hermes والاعتماديات ومزودي النماذج وخدمات القنوات التي تختارها قد يحتاج
الإنترنت وتكاليفه مستقلة. هذه النسخة ليست وضعًا بلا اتصالات خارجية.
الكود المتوافق القديم محفوظ حيث يفيد متابعة upstream؛ تعطيل ميزاته مقصود ومختبر.

## دمج تحديثات المطور

لا توجد طريقة تضمن عدم حدوث تعارضات. الدمج المنظم يكشفها ويحافظ على نسختنا.

1. احتفظ بكل تغيير في commit واضح، وتأكد أن شجرة العمل نظيفة.
2. نفّذ الأمر التالي من النسخة الشخصية:

```bash
node scripts/prepare-upstream-update.mjs
```

يجلب آخر `main`، يفحص رخصته، وينشئ وسم نسخة احتياطية وفرع مراجعة في مجلد آخر.
يجري دمجًا دون commit. لا يبدّل نسختك العاملة ولا ينشر شيئًا.

3. انتقل إلى مجلد المراجعة المطبوع، واقرأ الفروق:

```bash
git status
git diff --name-only --diff-filter=U
git diff --cached --stat
```

حل كل تعارض على حدة. لا تستخدم قبول نسختنا أو نسختهم لجميع الملفات. راجع خصوصًا
المصادقة، ترحيلات قاعدة البيانات، نقطة تسجيل المسارات، مسارات البيانات، حماية
الرخصة، تعطيل الربط الرسمي والمحدّث، والعربية. إذا دمج upstream مساهمة موجودة
عندنا فتحقق من السلوك واختباراته؛ لا تكرر الوظيفة لمجرد اختلاف commit.

4. ثبّت الاعتماديات، ثم افحص:

```bash
npm ci --ignore-scripts
npm rebuild node-pty
npm run license:check
npm run harness:check
npm run test:coverage
npm run test:personal
npm run test:e2e
npm run build
```

افحص المتصفح بالعربية والإنجليزية وتجربة دخول محلية واتصالًا مباشرًا. حدّث سجل
المساهمات وأساس النسخة في هذه الوثيقة. بعد نجاح المراجعة اعمل commit للدمج.
ارجع للمجلد الأساسي وادمج فرع المراجعة باستعمال `git merge --ff-only`.
إذا تطور الفرع الأساسي أثناء الفحص، أعد الدمج والفحص؛ لا تجبر الاستبدال.

5. خذ نسخة احتياطية من وحدات البيانات قبل نشر حاوية جديدة. التراجع عن الكود وحده
لا يعكس ترحيلات قواعد البيانات؛ استعادة النسخة القديمة قد تحتاج استعادة البيانات.

الاسم الجديد المستهدف للمستودع الشخصي الخاص هو `twuijri/core-hub` ووجهته `origin`.
يبقى الاسم `twuijri/agent-studio` حتى يدمج المالك تعديل توافق البناء ثم يعاد تسميته؛
راجع [هوية كور هب وخطة إعادة التسمية](CORE-HUB-BRANDING.md) للحالة والخطوات.
الدفع إلى `upstream` معطّل محليًا لمنع الخطأ. الفرع المحلي `personal/main`
يقابل فرع `main` في مستودعنا؛ افحص الوجهة قبل كل دفع ولا تستخدم force push.
رفع الكود أو بناء صورة لا يعني نشرها على سيرفر المستخدم.
